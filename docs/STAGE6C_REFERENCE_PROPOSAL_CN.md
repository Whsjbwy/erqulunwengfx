# 6C参考契约证据与另行审核提案

本文件只提出后续契约修订，**没有实现或修改冻结TerminalLOS内部规则**。

设参考长度为L，最后非零边长度为ℓ，冻结终端窗口参数为d=2m。现有切换阈值为：

```text
switch = max(L−ℓ,L−d) = L−min(ℓ,d)
```

因此同一直线几何只改变末边分段，也能改变终端模式阈值。实际解析测试使用长度10m的共线参考：末边0.5m时阈值9.5m，末边2m时阈值8m；虚拟进度8.1m时两种表示的终端模式不同。这证明表示依赖，不表示直线必然跟踪失败。

6C唯一适配`tail_arc_2m_v1`沿**原参考**定位L−2m，保留此前点，末尾用到真实goal的单条边重采样。原生控制不变、点序不反转、逐弦完整球认证；测试含原折线安全而替换弦穿障的拒绝反例。21条实际新参考全部通过认证，严格LOS由11/21变14/21：保持成功11、恢复3、退化0、保持失败7。

恢复的源任务为`climb--rrt--seed0`、`dive--rrt--seed0`、`F_B1--sst--seed1`。这里seed沿用6B标签，不是6C原生种子编号。改变的是参考整体，连带局部切向、投影、末边及路径长度相关仿真时限；不能将这3次恢复独占归因于终端时机。

剩余3条为tracking_error_limit，4条为到达但额外余量失守。后4条首次余量拒绝区间起点分别为141.4、18.3、11.3、35.3秒，两种参考完全相同；均早于新方案终端切换。**这4次余量失守并非首次由终端切换触发。** 原生控制轨迹仍全部安全，说明冻结闭环与该参考的偏差不能由原生证书自动覆盖；尚不能唯一归因于控制参数、路径局部间隙或其他因素。

新尾弦的长度可能小于2m，现有控制器仍按`min(ℓ,d)`切换，所以本适配未建立普遍的表示无关性。它是一次已认证的敏感性对照，没有成为C2默选后处理。C2继续使用6B密集加桥段契约，主指标为原生M，LOS单列为次指标。

建议研究者另行审核一个契约版本：保留完全相同的参考几何/点序，仅让终端触发位置明确依赖统一弧长`max(0,L−d)`，再与现行规则同源配对。该规则可能让目标捕获跨过最后拐角，必须继续逐区间安全认证，不能承诺全局收敛。若还要改变“参考精确终止goal”入口，也必须单独版本化，保持真实任务goal、0.75m到达球和全部安全约束，不把几何桥段计为原生控制。

上述提案当前未运行，不能将其作为6C成功率。完整证据见[c1_paired.csv](../results/stage6c/c1_paired.csv)、[四格统计](../results/stage6c/c1_transition_counts.csv)和[逐时刻记录](../results/stage6c/c1_terminal_events.csv)。
