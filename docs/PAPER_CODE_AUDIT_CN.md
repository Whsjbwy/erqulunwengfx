# G-Sunlight 论文与所提供源码审计

本文依据研究者提供的14页论文和 `LIU3Dsunlight-main.zip` 解压内容进行静态核对。源文件行号指所提供 ZIP 中的 `main_sunlight_3Dgrid.py` 与 `utils.py`，不是对未来上游版本的保证。静态疑点不等于已测得的失败；实际运行与碰撞证据另见阶段报告。

## 1. 研究对象与复现边界

论文为 Deng 等（2026），*Novel Sunlight Algorithm for AUV Fast Global Path Planning With Grid-Constrained Sampling*，[DOI: 10.1002/rob.70356](https://doi.org/10.1002/rob.70356)。作者仓库为 [breaker123344/LIU3Dsunlight](https://github.com/breaker123344/LIU3Dsunlight)。

论文页3将可行路径定义为起点和终点正确、整条连续路径均在自由空间内的路径。因此，只有顶点位于自由空间并不足以证明路径合法。论文没有明确规定占用体素面、棱、角接触的数值判定，也没有给出本示例通用的实体半径和动力学模型。本项目采用零半径折线及封闭障碍体素，接触即碰撞，并明确区分：程序能启动、产生路径、严格有效路径、论文主图表复现、实体可执行性。

所提供 ZIP 包含一个主程序、一个工具模块、`map.vti` 和简短 README；未见明确 `LICENSE`。本仓库不再分发这些材料，不给作者代码擅自附加许可证，仅发布独立编写的包装、验证器、测试、报告和精简结果。论文原件、ZIP、地图及本地诊断副本均留在仓库外。

## 2. 算法1—5与公式(1)—(6)

### 算法1：总体流程（页3）

输入为起点 `x_start`、终点 `x_goal` 和场景 `X`；输出为路径及有向图 `G=(V,E)`。初始化 `Openset`、图、候选路径集 `Pathset`、网格历史长度及搜索参数。每轮选取并移除太阳节点，先检查该节点到目标的连接；若可直连则记录完整路径，否则搜索障碍切点，经容量网格筛选后继续扩展。循环结束从 `Pathset` 选最优路径。

伪代码令 `i=0`，循环条件为 `Openset` 非空且 `i≤n_max`。直连成功后的 `continue` 会跳过末尾计数递增，故 `n_max` 本身不保证所有节点处理次数恰好等于该值。正文还明确说明 `ChooseSun` 包含启发式与概率机制；摘要的“deterministic”不能据此解释为无需控制随机源。

### 算法2：平面切点采样（页3—4）

围绕太阳节点按固定角步长辐射射线，沿射线以 `Δ_step` 前进直至碰撞。利用相邻射线的自由长度差与阈值 `L_thre` 比较定位障碍边缘；沿相应射线在较短长度基础上前进 `L_forward` 得到候选切点。此算法描述平面机制，不能替代三维连续碰撞检查。

### 算法3：三维锥形切点采样（页5）

输入包括太阳节点、两种角步长、长度差阈值、前进距离、径向步长及半锥角上限。以太阳到目标的方向为锥轴，遍历方位旋转 `φ∈[0,360°)` 和锥内偏角 `θ₁∈[0,θ̄₁]`，输出切点集。射线以固定步长累进，通过相邻射线长度突变寻找切点。伪代码的切点分支要求 `φ>0` 且 `θ₁>0`，长度突变使用严格大于阈值。

### 算法4与公式(1)—(3)：方向计算（页4—5）

由目标与当前点的坐标差计算方位角 `ψ` 和仰角 `θ`；坐标转换顺序为 `Z→Y→X→Y`。先组合 `Rz(ψ) Ry(θ) Rx(φ)`，再将基本方向经 `Ry(θ₁)` 转到世界坐标。公式(1)—(3)分别给出各轴旋转矩阵。论文采用 `Ry(θ)=[[cosθ,0,-sinθ],[0,1,0],[sinθ,0,cosθ]]` 的符号约定；所提供源码 `utils.py:154—180` 与此一致，不应擅自替换成另一常见约定。

### 算法5：网格容量约束（页5—6）

以 `sidelen` 划分空间，网格记录当前候选点及历史最短累计路径长度。新点如刷新历史最短长度则插入首位，否则插入第二位；加入 `Openset` 和图。超过容量 `cons` 时移除网格列表末点及其 `Openset` 记录。选取太阳节点后应从对应网格候选列表移除，但保留历史最短长度。

这些网格用于限制候选点数，不是路径必须经过的图搜索节点，也不能与原始地图占用体素混淆。`sidelen` 改变候选密度和搜索范围，`cons` 改变每个区域保留的备选数。

### 公式(4)—(6)：复杂度分析（页6）

公式(4)用最大射线长度与径向、角度步长约束二维切点搜索的 `CollisionFree` 调用数；公式(5)增加半锥角与第二角步长之比，得到三维调用数界。公式(6)将直连和切点搜索调用数合并，论证固定场景及固定步长等条件下对节点数的线性关系。空间分析另将网格总数和每格容量视为固定约束。

这些公式度量的是碰撞函数调用次数；调用本身的成本、数组重分配及排序等实现成本不由此自动消失。不能把一次示例运行时间或论文的理论论证扩展成任意地图、任意分辨率下的实测普遍线性结论。

## 4. 所提供代码的默认值与地图

`main_sunlight_3Dgrid.py:25—46` 指定相对地图路径 `./map.vti`、场景范围 `(0,100)×(0,80)×(0,80)`、网格边长5、容量1、`max_iter=100`、起点 `(2,2,2)`、终点 `(95,75,75)`、目标连线采样步长5、锥内角步长5°、半锥角30°、方位步长10°、`alpha=0.5`、`epsilon=0.8`。单位应以地图坐标为准；可视化轴写成m，并不使其自动等于表2的px或表3的海床场景。

原始VTI元数据为 `WholeExtent=(0,100,0,80,0,80)`、原点 `(0,0,0)`、间距 `(1,1,1)`、单位方向矩阵。由此点维度为 `(101,81,81)`，单元维度为 `(100,80,80)`；`obstacle` 是范围0—1的 `Float64` 单元数据。实际加载时仍需检查数据长度及数值语义。`utils.py:117` 采用x方向最快的VTK单元索引；`utils.py:136` 使用 `order='F'` 恢复三维占用数组。独立读取器必须核对这一布局，不能误用默认C顺序。

## 5. 论文与源码差异及需实验验证的疑点

| 项目 | 论文描述 | 所提供源码与影响 |
| --- | --- | --- |
| 目标直连时机 | 算法1先判断当前太阳节点到目标是否可直连 | `main:68—80` 先生成切点，再逐个判断切点到目标；无切点时 `continue`。不能视为相同控制流程 |
| 停止与路径集 | 算法1持续搜索到循环结束，再选 `Pathset` 最优项 | `main:105—116` 在首个产生可连目标切点的扩展轮次结束搜索；该轮仍可收集多个路径，再选最短者。不是在100轮内持续优化 |
| 迭代计数 | `i=0`，`i≤n_max`；直连分支跳过递增 | `main:56,69—70,117` 使用 `<max_iter`，无切点时也跳过递增；应分别记录太阳处理数与作者计数器 |
| 角上限 | 算法3包含 `θ₁=θ̄₁` | `utils:218` 的 `np.arange` 排除上限，默认采样偏角为0至25°，不含30° |
| 径向步长 | 三维几何实验给出 `Δ_step=5px` | `utils:242` 调用射线采样时明确传入 `step=1`；`main:41,80` 的5用于切点到目标的离散检查，二者不能混写 |
| 阈值及方向筛选 | 算法3使用长度差严格大于阈值，且要求 `φ>0` | `utils:247` 使用 `>=15`，没有 `φ>0` 条件，并要求相邻两条射线均以障碍终止。边界射线候选可能不同 |
| 网格插入和删除 | 非最优新点插入第二位，超容删除末点 | `main:82—100` 非最优新点追加末位，超容随机删除非首位点；当容量大于1时与论文不同，容量1不能代表该差异已经消失于所有流程 |
| 网格点移除 | 算法1从对应网格移除已选太阳点 | `main:65—68` 移除 `Openset` 项并加入 `Closeset`，未见对应 `grids_ids` 移除；`main:101—104` 对移除不存在的候选捕获 `ValueError`。需结合运行记录解释陈旧列表行为 |
| 候选优先级 | 正文描述排序并结合启发式概率选择 | `main:61—64,91—95` 按概率选择首项或随机项，新点只与首项比较后置首/追加，不是完整累计长度排序 |
| 候选连边验证 | 可行路径应整段在自由空间 | `utils:247—259` 按射线长度差生成切点，`main:77—80` 直接记入父边，只检查切点到目标。不能仅由顶点生成推断父边严格安全 |
| 边界检查 | 场景与路径应属于自由空间 | `utils:258` 只比较切点坐标上界，未检查下界；离散路径检查另行处理越界。是否出现越界须由真实路径证据确认 |
| 连续碰撞 | 论文定义要求整条路径无碰撞 | `utils:263—283` 用间隔采样查询占用，跳过端点；长度不大于步长时直接返回无碰撞。薄障碍、接触和端点问题必须独立复检 |
| 后处理 | 总体算法输出路径；正文未完整说明此代码的五轮操作 | `main:161—165` 五次后处理并反转方向；`utils:293—318` 仍调用离散检查并移动中间点。原始与后处理路径必须分别验证 |
| 时间口径 | 论文给出规划运行时间，但实现细节不足 | `main:24,143,161—168` 计时含读图及前期绘图准备，截止于后处理之前；末尾打印的处理后长度与同一前期耗时并非全流程耗时 |
| 随机性 | 页3承认概率选择 | `main:61—64,98` 使用 `random` 和NumPy随机数，入口没有种子参数；固定两个随机源并记录适配方式 |

## 6. 第一阶段应据实回答的问题

1. 原版实际命令是否启动、以什么退出码结束、是否受到GUI或依赖限制；固定种子包装和仅渲染适配分别完成多少次。
2. 原始及后处理路径分别产生多少、严格有效多少；失败须给首次碰撞线段和体素等证据，不能只报告平均长度。
3. 哪些论文数据、对比算法和实体条件没有提供或没有执行；仅用本仓库单地图实验不能宣布表1—3及实体实验已完整复现。
