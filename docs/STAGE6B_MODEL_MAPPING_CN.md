# 阶段6B模型、原生接口与参考契约映射

本文核对[冻结协议](STAGE6B_PROTOCOL_CN.md)、[配置](../configs/stage6b_protocol.json)、独立原生适配器与冻结Python实现之间的实际对应关系。构建和命令证据分别见[构建记录](STAGE6B_BUILD_CN.md)、[命令记录](STAGE6B_COMMANDS_CN.md)。本阶段是开发场景上的正确性与资源冒烟检查；两个算法各18次任务，不能把混合36次执行总账当成某个算法的性能估计。

## 状态、控制与单位

实际搜索状态为五维 `q=(x,y,z,ψ,θ)`，空间为 `R³ × SO(2) × [-20°,20°]`。原生JSON和Python `State`均存储六项 `[x,y,z,yaw,pitch,speed]`，第六项是必须等于 `1 m/s` 的冻结参数，不是额外搜索维度，也不是可采样速度或停车控制。进入原生状态映射前先检查初态速度，避免映射时固定写回 `1` 掩盖非法输入。

| 项目 | 实际映射与约束 |
| --- | --- |
| 位置 | 米；`z`向上为正，正俯仰使车辆上升 |
| 姿态 | yaw、pitch使用弧度；yaw规范到 `[-π,π)`，终点姿态不约束 |
| 两个控制 | `uψ=dψ/dt`、`uθ=dθ/dt`，均为Euler角速率，单位 `rad/s` |
| 速率边界 | `|uψ|≤π/18`（10°/s），`|uθ|≤π/36`（5°/s）；超限拒绝，不截断后再认证 |
| 俯仰边界 | `|θ|≤π/9`（20°），比较容差 `1e-12 rad`；候选越界即拒绝 |
| 传播时间 | 冻结区间 `dt=0.1 s`；规划控制持续1—50个完整区间，即0.1—5秒 |
| 目标 | 到真实 `scene.goal` 的位置欧氏距离 `≤0.75 m`，含等号 |
| 距离度量 | 位置、SO(2)和俯仰三个子空间权重各1，未按结果调节 |

连续模型为：

```text
dx/dt = v cosθ cosψ
dy/dt = v cosθ sinψ
dz/dt = v sinθ
dψ/dt = uψ
dθ/dt = uθ
v = 1 m/s
```

这里的Euler角速率不表示用显式Euler法积分位置。`native/stage6b/model.cpp::integrate`与冻结 `stage5a/tracking.py::integrate`均对恒速、恒定两角速率作解析积分，使用 `ψ±θ` 的三角积分及零速率连续极限；同时偏航、俯仰也按同一公式处理。该模型是无洋流、只前进的运动学假设，不含滚转、加速度、流体动力或6DOF辨识。

保守球体沿用长度2米、直径0.4米圆柱的外接球，再加0.25米安全余量：

```text
Rbody = sqrt(1² + 0.2²) = sqrt(1.04) m
Reffective = sqrt(1.04) + 0.25 ≈ 1.2698039027 m
```

原生读入半径必须与该冻结值相差不超过 `1e-12 m`。规划认证使用完整 `Reffective`；LOS仍沿用冻结的物理球、任务球及额外0.25米余量三类判据，严格执行成功要求全程保持额外余量。

## 体素、闭集接触与连续区间认证

`stage6b/scenarios.py`将占用布尔数组转换为 `uint8`，按NumPy **C-order**输出。形状 `(nx,ny,nz)` 中索引 `(i,j,k)` 的偏移严格为 `((i*ny)+j)*nz+k`。原生输入同时携带 `shape/origin/spacing`，检查正尺寸、有限坐标、正间距、0/1值、完整字节数及无尾随数据；物理网格和虚拟顶界网格必须同坐标框架。二进制网格仅放在仓库外，同语义地图复用一份，不以转置或重采样改变场景。

占用体素是包括面、棱和角的闭合轴对齐盒。线段到盒的距离通过各坐标穿越盒面的位置划分参数区间；每段距离平方为二次函数，解析检查驻点与端点。球扫掠要求整条弦到每个候选盒的最小距离大于 `R+1e-9 m`，接触也拒绝；不是只查起终点或离散空间采样。宽相位仅筛选保守包围盒，不能替代解析最小距离。工作空间边界遵循冻结的完整球容纳约定，恰好容纳允许，超出拒绝；此边界约定与占用盒接触拒绝分别实现。

每个0.1秒ODE区间的真实曲线另用下式包络：

```text
ε = v * hypot(uψ,uθ) * dt² / 8
```

原生和Python都以 `Reffective+ε` 认证端点弦，从而覆盖区间内弯曲运动；不能用只认证裸弦来代替曲线证书。物理障碍、工作空间边界和可选任务顶界分别保留原因。余量字段是含曲线偏差的保守下界，并受冻结3米clearance查询上限截断，不能理解为无截断的精确净空。

[中段反例](../results/stage6b/middle_collision.json)使用冻结速度、零角速率和0.1秒区间：两端球均自由，中点净空约 `-0.0004 m`，整段拒绝。拒绝候选端点不是实际首次接触位置；证据中的中点球相交用于单独证明真实区间穿障。

## 真实OMPL传播接口与拒绝语义

`ompl_runner.cpp`建立官方 `control::SpaceInformation`、两维 `RealVectorControlSpace`、显式状态有效性检查器和 `CertifiedPropagator`。传播器逐个0.1秒区间执行模型和完整球扫掠检查，不允许后向传播。区间失败时写出一个有限、明确位于状态边界外的sentinel；它必须被有效性检查器拒绝，不能让OMPL把最后一个安全位置误当作本段已完成。

`propagateWhileValid`拒绝一步后可把有效源状态返回给调用者，因此 **`isValid(returned_state)`不能证明运动已接受**。实际适配验收同时检查接受步数：合法区间应为1，拒绝区间应为0；并核对合法返回候选、拒绝返回源状态。非法冻结速度在映射前拒绝。原生输出区分最后接受状态与最后候选状态，并保留propagator调用、已检查区间、接受区间和拒绝原因计数。

本机[接口总账](../results/stage6b/interface_acceptance.json)已记录13/13符合预期：真实适配器调用936次，接受930个完整区间；相对冻结Python的最大位置、角度/速度比较差均为0，28个独立RK4核对的最大位置差为 `1.2079226507921703e-13 m`。这些是给定控制接口证据，不是搜索成功率。Windows原生CTest实际1/1通过，单个测试内部含6组模型/几何检查；这不能替代上游OMPL全测试、项目全量pytest或最终云端CI结论。

## 官方规划器、目标、代价与随机性

独立CMake通过 `find_package(ompl 2.0.2 EXACT CONFIG REQUIRED)`链接官方 `ompl::ompl`，直接构造官方 `control::SST`和 `control::RRT`，未修改树核。两者使用相同状态空间、控制边界、0.1秒传播步长、1—50步持续范围和0.05目标偏置；SST选择/稀疏半径为官方默认0.2/0.1。RRT使用官方 `SimpleDirectedControlSampler`且候选数为1，SST使用官方均匀控制和整数持续步数采样；共享采样边界与支持不表示树逻辑相同。

保留上游语义差异：SST只有采样整段均有效才保留扩展；RRT可保留满足最短持续步数的有效前缀。不能把这种差异改写成统一自编扩展器。状态目标只依赖位置，采样目标位置时随机采样允许的yaw和pitch。

通过官方 `ControlDurationObjective`提供代价，官方实现每段控制成本为 `steps*dt`。因 `v=1 m/s`，累计持续时间与实际运动弧长 `v*T` 数值相等；不能把普通状态间弦长目标当成同一控制代价。RRT按官方首次到达逻辑结束；SST通过官方目标API将代价满足阈值设为正无穷，使第一条有限代价exact解满足阈值并返回。外层停止条件还包括8秒上限或已登记exact解，不用只有状态的中间回调充当控制证书。该阶段检验首次exact结果，不声称得到长时间优化后的最优解。

官方OMPL把首次设置的seed=0替换为1。预登记标签0/1固定映射为原生1/2，CSV同时保留 `seed_label`和 `ompl_seed`；每任务启动新原生进程，在任何OMPL RNG构造前调用 `RNG::setSeed`。两个直线pilot原位复用到36任务中，不额外补跑或按结果挑种子。定时终止仍会受执行机器和负载影响，固定随机种子不等同跨机器逐节点或逐时刻一致。

六个解析正例的注册目标由冻结给定控制生成，控制仅作为隐藏可达见证，不进入搜索请求。三个旧F场景仅标注几何已知可达、运动学可达未知，是历史开发图，不能称为新独立留出集。

## 独立PathControl审计与冻结LOS参考

原生返回官方 `PathControl`的控制、持续时间及稀疏节点，节点数必须等于控制数加1。原生先逐区间自证；独立Python再从注册初态重新积分全部控制，逐个0.1秒区间检查状态、速率、完整球扫掠、顶界及目标。节点位置比较容差为 `1e-10 m`，SO(2)角差、俯仰和速度为 `1e-12`；独立RK4用每个选中区间50个子步核对首/中/末区间。不是对每个区间都重复RK4，也不是信任原生自证代替独立重建。

`approximate`可以拥有安全的控制前缀，但不升级为严格模型成功；exact必须独立审计通过且最终位置满足真实目标球。原生与LOS使用同一个显式 `scenario.initial`：解析左右弧保持注册yaw=0及其他姿态，不能被LOS默认朝向目标的初始化替换；历史F场景使用冻结的朝向目标yaw、零俯仰和1米/秒。

LOS输入从独立重建的全部0.1秒位置端点组成，保留起点至终点顺序，不平滑、捷径化或修改控制。每条参考弦另以完整 `Reffective`认证，ODE曲线则保留前述加大半径证书，两种对象分别检查。

OMPL只需到达0.75米目标球，冻结LOS入口却要求参考最后一点等于真实 `scene.goal`。适配器仅允许追加长度 `≤0.75 m`、经完整球余量认证的直线**参考桥段**，保留真实goal并单列长度和适配耗时。桥段没有原生控制证书，绝不能计入原生可行控制路径或称为原生执行。桥段或参考弦认证失败保留为接口拒绝，计入总任务K，不计入实际合格LOS执行E。LOS继续使用冻结 `stage5af los_terminal_v1`、原积分、内环、停止顺序和全部安全/到达阈值。

### 密采样下的末端触发边界

冻结 `TerminalLOS`实际采用命令前虚拟进度：

```text
switch_progress = max(last_nonzero_edge_start, L - 2 m)
```

因此切换时剩余参考弧长为 `min(last_nonzero_edge_length,2 m)`，并不保证在距离末端2米时触发。本阶段0.1秒采样形成约0.1米的原生参考弦；有非零末端桥段时，最后一条边通常就是该桥段。对本次21条合格参考，桥长均非零且为0.32909—0.74971米，所以末端锁存阈值距参考末端的剩余弧长就是桥长，短于2米；没有桥段时通常约为最后0.1米弦长。这里说的是虚拟参考进度，不是车辆到goal的欧氏距离。

只读现有完整轨迹可见：6条 `tracking_error_limit`各记录1次末端切换；4条 `goal_reached_required_margin_violated`和11条严格成功均未发生末端切换。该分布只能作为后续诊断线索，尚无隔离对照证明密采样或切换阈值是失败唯一原因。正常LOS还使用各条参考弦的局部切向，原生控制可行也不保证冻结LOS能重现该控制。阶段6B保留全部10条原生可行但LOS严格失败结果，不为补成功而修改控制器或参考处理规则。

## 分母和端到端时间

| 记号 | 口径 |
| --- | --- |
| K | 每个算法18条全部注册任务；approximate、无解、过期和接口失败仍保留 |
| M | exact、完整独立证书合格且规划总计时不超过10秒的模型可行任务 |
| E | 通过参考接口并实际运行的合格LOS任务；接口拒绝不计E |
| S | LOS达到目标、全程满足额外0.25米余量，且满足执行及单流程时间上限 |
| M/K | 原生开环模型可行比例 |
| S/E | 在实际合格LOS执行中的严格成功比例 |
| S/K | 从全部注册任务起算的严格端到端成功比例 |

规划总预算为10秒，其中搜索最多8秒，公共收尾预留2秒属于该10秒。计时从请求序列化前开始，涵盖原生进程、求解、原生证书、结果读取和独立Python控制证书；独立证书超过10秒即 `deadline_rejected`，不能只凭 `solve()`耗时计M。输入地图缓存属于共同场景准备，模型与语义地图在运行前已冻结。

参考适配及冻结LOS另有共同20秒上限，规划证书加参考适配/执行的单流程上限为30秒。S同时检查20秒和30秒条件；到达但额外余量违反、执行过期或流程过期均不能算严格成功。完整计时列和失败原因保留在[逐次CSV](../results/stage6b/planning_runs.csv)。

[执行总账](../results/stage6b/experiment_accounting.json)记录36条真实任务均已执行，其中21条模型合格、21条合格LOS执行、11条严格LOS成功，另15条为approximate；这些总数用于核对记录完整性。算法比较应分别按各自18条任务报告M/K、S/E、S/K，并保留场景和种子配对，不据开发冒烟矩阵宣称优越性或泛化结论。最终项目检查和云端CI需由对应真实记录支持，本文不预先声称通过。
