## 顺序与停止门槛

1. B0：官方OMPL 2.0.2与Boost/Eigen用同一LLVM-MinGW工具链在Windows原生构建；没有用自写SST代替官方算法。工具、构建、完整日志均在仓库外D盘专属目录，无系统级安装或WSL切换。
2. B1：完整重放6A已登记12例，再做冻结0.1秒内端点自由、中段球相交的第13例。逐步对比冻结Python积分、独立RK4、状态/率限制、完整球扫掠和顶界，任何不一致停止搜索。位置容差1e-10米、角度/速度比较1e-12，远大于预期舍入误差但不足以掩盖0.4毫米穿入反例。
3. B2：先两个直线任务，之后最多36次（9任务×2算法×2种子标签），首轮原位复用。6个解析任务的控制只作为隐藏见证；3个旧F图只能标几何已知可达、运动学未知，不称新留出集。
4. B3：返回的exact/approximate控制均独立逐区间审计；只对严格合格exact参考运行冻结LOS。开环`M/K`与跟踪`S/E、S/K`分别记录，没有把approximate升级为成功。
5. B4：真实CSV、失败原因、必要轨迹图、构建和检查证据、中文报告及堆叠PR；最后给Go / Need More Evidence / Pivot并停止等待审核。

## 参数与计时

完整预登记见[配置](../configs/stage6b_protocol.json)。SST使用官方默认选择/稀疏半径0.2/0.1；两者同一控制范围、1—50个0.1秒传播步、0.05目标偏置和状态距离权重。保留SST拒绝未完成整段、RRT可接受有效前缀的原算法差异。只通过官方目标API采用恒速弧长代价，不改树核。

OMPL官方实现把seed=0替换为1。为避免标签0和1得到同一个原生种子，在任何搜索前固定映射：标签0→原生1，标签1→原生2；每任务新进程，在构造任何OMPL RNG前设置，CSV同时保留两列。没有测试后挑选种子。

统一10秒规划总预算包含请求序列化、原生进程、求解、结果读回和独立控制证书；搜索最多8秒，预留的2秒不是额外预算。只统计10秒内完成严格证书的解；过期保留为`deadline_rejected`。LOS参考适配与执行另有所有方法相同的20秒上限，单流程总上限30秒。计时不能只用OMPL的solve调用值。

## 统一参考契约

原生轨迹按0.1秒独立重建位置参考，原样保留点序，不平滑、不优化。每条参考弦与ODE曲线分别认证。OMPL目标为距真实goal≤0.75米；冻结LOS入口却要求参考末端精确为真实goal。只允许追加≤0.75米、经完整余量认证的**参考桥段**，单列长度/认证/耗时，不能算原生控制轨迹，也不改变scene.goal。桥段拒绝列为接口失败，不计入实际执行分母E。

所有方法与LOS使用完全相同的显式初态；6A左右弧不得被默认goal-facing初始化改成±45度。冻结控制器与阈值不变。任何原生可行、LOS失败的差异均保留，不能据此修改控制或宣布规划器无效。

本阶段没有H1、洋流、MPC、强化学习、Attention或6DOF；不会运行324任务论文矩阵或生成新独立地图。任何依赖/模型/认证问题先留证据、停搜索，不能靠降低安全要求继续。
